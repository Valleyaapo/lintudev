## 2024-05-14 - Fix Contact Form XSS and Error Leakage
**Vulnerability:** Contact form submissions were interpolating raw user input directly into an HTML email body, enabling Cross-Site Scripting (XSS) / HTML injection risks if the form was abused. Also, the 500 error responses were dumping the raw error objects/messages to the client, leading to potential information leakage, and lacked input length validation leading to DoS risks.
**Learning:** This existed because the `resend` API expects an `html` property for the email body, and standard string interpolation was used without considering that emails render HTML. The error details were likely left over from early development.
**Prevention:** Always manually sanitize untrusted user input before passing it to systems that render HTML (like emails). We implemented an `escapeHtml` utility in `src/utils/sanitize.ts` and used it for interpolation. Never return internal error stacks or full error objects in external API responses; instead, return a generic message. Implement length limits on free-text inputs.
