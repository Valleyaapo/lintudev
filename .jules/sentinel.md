## 2026-03-03 - Prevent XSS and Information Leakage in Contact API
**Vulnerability:** Contact form API passed user input (name, email, message) directly into the Resend email HTML body without escaping, allowing XSS if viewed in an email client. Additionally, the API lacked input length limits (leading to potential DoS/abuse) and returned unhandled internal error structures (stack trace leakage on 500 error).
**Learning:** Email bodies are rendered as HTML by default by email providers. User input must always be sanitized/escaped before being interpolated into HTML template literals. The `reply_to` and `subject` headers are treated as raw strings and do not require HTML escaping. Also, internal framework structures (`import.meta.env`) require specific local mocking techniques when executing route handlers outside the Astro context.
**Prevention:** Implement and reuse a dedicated `escapeHtml` utility for all user input injected into HTML templates. Implement input validation limits on incoming request data. Always return generic error messages for 500 status codes without exposing internal `error.message` or stack traces.
